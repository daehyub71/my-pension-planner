- **2026-09-13 M6 · 공개 저장소 전에 실데이터가 문서·테스트에 들어 있었다.** 파일(xlsx·pdf)은 한 번도 커밋되지 않았지만, SPEC §3의 생년월·국민연금 월액·적립금·가입일, 실데이터 전용 테스트의 기대값, 합성 픽스처에 섞인 실제 가입일, 코드 주석의 생년월이 추적 파일에 있었다. → 실데이터 전용 테스트는 `data/private/expected-real.json`(git 제외)에서 기대값을 읽고, 일반 테스트·주석·문서는 합성 K씨 값으로 바꿨다. 과거 커밋에도 값이 남아 있어 **공개 저장소는 정리된 트리를 새 이력(커밋 1개)으로 올린다**(사용자 결정). 옛 이력은 로컬 백업 브랜치에만 둔다 — **절대 푸시하지 않는다**. 점검용 값 목록은 `data/private/sensitive-values.json`.

- **2026-09-13 M5 · 법규 검색이 「안 되는」 것처럼 보였고, 링크에 키가 새고 있었다.** ① 키가 없으면 법제처 링크만 냈다 — 모아 둔 발췌도 검색하지 않았다. ② 키가 있어도 DRF `lawSearch`는 **법령명** 검색이라 「분할연금」이 0건이었다(본문 검색 `search=2`는 가나다순 371건이라 쓸모없음). ③ **응답의 `법령상세링크`에 요청 키(OC)가 그대로 들어 있어** 그 링크를 화면에 걸면 키가 노출된다. → 발췌를 먼저 검색(띄어쓰기 무시, 네트워크 없음) · 키가 있으면 법령명 결과를 덧붙임 · 링크는 `law.go.kr/법령/{법령명}` 공개 주소로 새로 만든다. 사용자 제보로 발견.
- **2026-09-13 M5 · 키 미등록 시 `.env.local`의 키를 쓰게 했다(사용자 요청) — 개발 서버에서만.** 정적 사이트는 런타임에 파일을 못 읽으므로 `next.config.ts`가 `NODE_ENV=development`일 때만 `LAW_OC`를 `NEXT_PUBLIC_LAW_OC_DEV`로 넣는다. 배포 빌드(`out/`)에 키가 없음을 확인(0개 파일). 키는 `.next/dev`(git 제외 개발 캐시)에만 있다. **M6-4 보안 점검에서 `out/` 키 검사를 다시 한다.**

- **2026-09-13 M4 · 국민연금 개시를 옮길 때 그 사이 물가 반영을 빼먹었다.** 포털 월액은 원래 개시 해(65세)의 명목 금액인데, 연기·조기 때 가산·감액 계수만 곱했다. 그래서 연기는 실제보다 불리(70세 수령액 약 −9%, 손익분기 94세대)하고 조기는 유리(약 +17%, 86세대)하게 나왔다. 계수에 (1+물가)^(개시 나이 차)를 함께 곱해 고쳤다 — 수정 후 손익분기가 연기 80세대·조기 75세대로 알려진 범위와 맞는다. 「둘 다 받는 나이에서 비율 = 계수」 불변식을 테스트로 잠갔다. 사용자가 시나리오 화면 값이 이상하다고 해 실데이터로 재현하다 발견.

- **2026-09-13 M4 · 91세 이후 국민연금이 0 이었다.** 포털 엑셀은 90세에서 끝나는데, 가정을 바꾸지 않은 국민연금은 원본을 그대로 통과(pass-through)시키며 없는 나이를 0으로 채웠다. 기대수명 95세면 91~95세가 월 지출 전액 부족분으로 잡혀 필요 금융자산이 부풀었다(실데이터에서 필요 금융자산이 약 14% 부풀었다). 원본이 끝난 나이부터 앵커 산식(오차 0)으로 잇는다 — 종신연금이라서. 사적연금은 지어내지 않는다. 사용자 질문(「8.88억은 연금을 뺀 금액인가」)을 따라가다 발견.

- **2026-09-13 M2 · 조문 대조(korean-law-mcp)로 연금보험 과세가 틀린 것을 찾았다.** 연금계좌는 퇴직연금계좌와 「연금저축」 명칭 계좌뿐이다(소득세법 시행령 제40조의2 ①). 일반연금보험 지급액은 연금소득이 아니라 보험차익(이자소득, 제16조 ①9)이고 10년 유지 등 요건을 채우면 비과세다. 규칙을 `tax.insurance_gain_exempt`로 바꾸고, 「연금저축보험」이 `/보험/` 정규식에 걸려 insurance 로 분류되던 임포터도 고쳤다.
- **2026-09-13 M2 · 건보 소득에 사적연금이 들어가는지(R-2)는 조문 문언과 실무 설명이 다르다.** 시행령 제41조 ①5·시행규칙 제44조 ①5는 「소득세법 제20조의3」 전체를 가리킨다. 반영 여부를 뒤집으면 실데이터 피부양자·보험료가 크게 바뀌므로 공단 확인 전까지 값은 두고 등급만 estimated 로 남겼다.
- **2026-09-13 · korean-law-mcp 는 MCP 연결 없이 CLI 로 쓴다.** `LAW_OC` 는 `.env.local`(git 제외)에서 읽고 출력에서 가린다. `npx -p korean-law-mcp korean-law get_law_text --mst <MST> --jo "제N조"`. 현행 MST: 소득세법 280405 · 시행령 286211 · 건보법 시행령 283469 · 시행규칙 288087 · 장기요양법 시행령 286011.

- **2026-09-13 M2 · 규칙 파일의 점당 금액 208.4원은 2025년 값이었다.** 2026년은 211.5원(보건복지부 보도자료). 건강보험료율 7.19% · 장기요양 0.9448% 와 함께 `web` 등급·확인일로 고쳤다.
- **2026-09-13 M2 · 연금수령연차는 「처음 받은 해」가 아니라 「받을 수 있게 된 해」부터 센다.** 55세에 수령 가능해진 계좌를 60세에 개시하면 첫해가 이미 6년차다. 처음 쓴 테스트가 개시 연도를 1년차로 잡아 틀렸다. 이연퇴직 감면(70→60%)만 실제 수령연차로 센다.
- **2026-09-13 M2 · 연금 말고 소득이 없으면 1,500만 이하여도 종합과세가 저율보다 싸다.** 2,000만 전액 16.5%(330만) vs 종합(연금소득공제 690만 → 약 77만). 그래서 이하·초과 모두 두 방식을 계산해 싼 쪽을 고른다.

- **2026-09-09 M0 · npm 의 `xlsx@0.18.5`는 취약점(프로토타입 오염·ReDoS) 수정본이 없다.** SheetJS 는 0.19 이후 npm 에 올리지 않는다 → `package.json` 에 공식 CDN tarball(`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`)로 고정. `next` 16.3.4 · `pdfjs-dist` 6.2.108+ 로 올려 `npm audit` 0건.
- **2026-09-09 M0 · pdfjs 텍스트 조각은 셀이 여러 줄로 쪼개지고, 셀 하나가 페이지 경계에서 잘린다.** 실측: 3쪽 머리의 「평생연금」「저축」은 2쪽 마지막 행(연금저축펀드 상품명)의 뒷조각이다. 파서는 행 앵커(「계약상세」 버튼)에서 40px 밖의 조각을 직전 행에 이어 붙인다. 합성 픽스처도 같은 기하를 재현한다(`rowStartY`).
