## 1. 프로젝트 목표

통합연금포털 내연금조회는 3층(국민·퇴직·개인) 연금의 연령별 예상 수령액을 그래프로 보여준다.
그런데 그 숫자는 사실이 아니라 **시나리오**다 — 물가 3.1%, 만 60세 개시, 상품별 운용수익률이라는 포털의 가정이 박혀 있다.
화면 우하단 "산출가정 변경" 버튼이 그 증거인데, 가정을 바꾸면 화면이 통째로 갈아치워져 **나란히 볼 수 없다.**

포털이 못 하는 다섯 가지가 이 프로젝트의 이유다.

```
① 시나리오를 나란히 못 본다           → 시나리오 A/B/C 동시 비교
② 실질가치가 없다 (명목 3.1% 착시)      → 물가 반영 실질 축 토글
③ 인출 전략을 못 다룬다               → 개시 시점·기간 파라미터화
④ 세금·건보료가 없다                  → 연금소득세 · 1,500만 기준선 · 피부양자 2,000만 경계
⑤ 절벽·크레바스를 경고하지 않는다      → 위험 구간 자동 표시
```

**한 줄 정의:** "지금 내 연금으로 뭐가 되나"를 실데이터로 진단하고, 가정을 바꿔 나란히 비교하고, 세후·건보료를 반영한 가처분으로 본다.

리서치 ①의 결론이 위치를 정한다 — "가정을 넣어 목표액을 구하는" 계산기는 포화이고,
"내 실데이터에서 출발해 진단하는" 도구는 없다. 데이터를 못 가져오기 때문이다. 우리는 포털 엑셀 다운로드라는 답을 안다.
**수동 임포트가 진입장벽이자 해자다.**

## 3. 실측 근거 (2026-09-09 파일)

설계가 기대는 사실들이다. 골든 테스트(N3)의 원천이기도 하다.
> **공개 저장소 대비 (2026-09-13)**: 실데이터의 금액·생년월·가입일·금융회사는 이 문서에서 지웠다. 예시 값은 합성 K씨(1968-07생) 기준이고, 실데이터 기대값은 `data/private/expected-real.json`(git 제외)에만 있다.

### 3-1. 엑셀 (`100lifeplan_*.xls.xlsx`, 이중 확장자이나 정상 xlsx)

| 위치 | 내용 |
|------|------|
| row 1 | `단위 : 천원` + 생년월(`1968년07월` 형식) |
| row 2 | 헤더 — `연령`, `55세`…`90세`(36개), `소 계` |
| row 3~ | **상품 1건 = 1행**, 마지막 데이터 행은 `합계` |
| col A (숨김) | 연금 유형 코드 **3=국민 · 2=퇴직 · 1=개인** |
| col B | 본인/가족 |
| col C | 기관명 — 전각공백(U+3000) 패딩 → strip |
| col D | 상품명 — `노령연금(개시전, 현재가치 0%)`처럼 가정이 박혀 있음 |
| col E | 개시 시점 — `2033년 08월` / `2031년` **두 형식** |
| col F~AO | 연령별 **연간** 수령액(천원). 개시 첫 해는 부분연도 |
| col AP | 소계 |

문자열은 `sharedStrings`가 아니라 **`inlineStr`**(`<is><t>`)이다. XML은 utf-8.

### 3-2. 계약정보 PDF (`연금_*.pdf`, 3쪽)

| 절 | 내용 |
|----|------|
| 국민연금 | 노령연금(개시전) · 개시 연도 · **예상 월액(원)** · 미래가치 "미제공" |
| 퇴직연금(DB) | 1건 "퇴직금정보 미입력" — DB→DC 전환 껍데기(P-6 해소). 전망 누락 없음 |
| 퇴직연금(DC·IRP) | 계좌별 적립금(원) · 가입일 · 개시예정일 · 조회기준일 |
| 개인연금 | 연금저축펀드 · 일반연금보험 — 적립금 · 가입일 · 개시예정일 |
| 유의사항 | **개시예정일은 만 60세 가정** — 확정이 아니라 파라미터다 |

텍스트 추출 시 표 셀이 줄바꿈으로 쪼개진다(예: `123,45` / `6,789`). 파서는 숫자 조각을 재조립해야 한다 (P2).

### 3-3. 역산 · 관찰

- **포털 산식 재현 오차 0**: 국민연금 = 월액 × 개시 첫해 개월 수(예: 8월 개시면 5개월) · 이후 매년 ×12×1.031. 포털 가정 = **물가 3.1%/년, 명목 표시**. 실데이터 26개 값 오차 0(로컬 검증)
- **절벽은 하나가 아니다**: 실데이터에서 연금저축 종료와 DC·IRP 동시 종료로 두 곳(−20%대, −50%대)이 나왔다 → 절벽은 임계치 규칙(F7), "80세" 하드코딩 금지
- **크레바스는 은퇴 나이에 달려 있다**: 개인연금만 받는 구간 → 퇴직연금이 더해지는 구간 → 국민연금이 더해지는 본궤도. 소득이 언제 끊기느냐가 포털 데이터에 없다 → 은퇴 나이 필수 입력(F3)
- **명목 착시**: 90세 명목 합계가 80세보다 크다 — 국민연금 3.1% 복리 때문 → 실질 토글(F6)의 존재 이유
- **연금보험**: 명목 고정 + 5년마다 보너스. 실질로는 매년 줄어드는 상품
- **적립금 → 수령총액 배율**(포털 운용수익률 가정이 숨어 있다): 계좌마다 다르다(약 ×1.3~×3.4). 배율에서 내재수익률을 역산해 "포털 가정" 시나리오의 초기값으로 쓴다 (F4)

## 6. 데이터 모델

```ts
type AccountKind = "national" | "dc" | "irp" | "savings" | "insurance" | "db" | "housing";

interface Account {
  kind: AccountKind;
  owner: "self" | "family";
  institution: string;          // 전각공백 제거
  product: string;
  joinDate?: string;            // PDF (YYYY-MM-DD)
  startDate: string;            // 엑셀 E열 → YYYY-MM (월 없으면 -01 + 경고)
  balance?: number;             // PDF 적립금(원). 국민연금은 없음
  monthlyAmount?: number;       // 국민연금 예상 월액(원) — 앵커
  asOf?: string;                // 조회기준일
  flowByAge: Record<number, number>;  // 연령 → 연간 수령액(천원), 포털 원본
  sourceMix?: { exempt: number; deferredSeverance: number; taxable: number; deferredSeveranceTax?: number };  // F8 ①, 선택 (이연퇴직소득세 2026-09-13 추가)
}

interface Inputs {
  birthYearMonth: string;       // 엑셀 row 1
  retireAge: number;            // 필수 (D3)
  targetMonthlySpend: number;   // 현재가치, 만원
  lifeExpectancy: number;       // 기본 95
  financialAssets?: number; annualFinancialIncome?: number; propertyTaxBase?: number;
  spouseEmployed?: boolean; npsTaxableRatio?: number;
}

interface Assumptions {
  inflation: number;                            // 기본 0.031 (포털)
  returnByKind: Partial<Record<AccountKind, number>>;  // F4 역산값이 기본
  npsStartAge: number;                          // 60~70
  privateStart: Partial<Record<AccountKind, { age: number; years: number }>>;
  housing?: { startAge: number; monthly: number };
  targetMonthlySpend?: number;                  // 시나리오 「지출 조정」 (2026-09-13 추가, M4)
}

interface Scenario { id: string; name: string; assumptions: Assumptions; createdAt: string }
interface Snapshot { asOf: string; accounts: Account[]; inputs: Inputs; rulesVersion: string }
interface Rule { id: string; value: unknown; source: string; grade: "verified" | "web" | "estimated"; checkedAt?: string; note?: string }
```
